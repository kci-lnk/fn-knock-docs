# ゲートウェイ内蔵ページ

Go ゲートウェイは、Host またはパスマッピングのアップストリームへ転送する前に、予約済みパスを処理します。これらのページに専用マッピングは不要です。リクエストが実際にゲートウェイ入口へ届くサブドメインであれば、内蔵パスを付加して開けます。

たとえば、次の URL は `nas.example.com` や `auth.example.com` のアップストリームではなく、ゲートウェイ自身が応答します。

```text
https://nas.example.com/__select__
https://auth.example.com/__wol__
```

ここでいう「任意のサブドメイン」とは、DNS、ポート転送、またはトンネルにより、その HTTP/HTTPS リクエストが fn-knock ゲートウェイへ届くサブドメインです。サブドメインマッピングを別途作成する必要はありません。証明書は使用するドメインをカバーし、手前の CDN、リバースプロキシ、トンネルは元の `Host` を保ったままゲートウェイへ転送する必要があります。内蔵パスは Web ゲートウェイ専用であり、管理入口、TCP/UDP ストリームマッピング、直接モードの元ポートには使えません。

パスは完全一致が必要です。`/__select__` と `/__wol__` の末尾に `/` を付けないでください。クエリパラメーターは利用できます。ゲートウェイ可視性、WAF、グローバルブロックリスト、リバースプロキシのスロットリングはページを返す前にも実行されるため、リクエストをブロックする場合があります。

## 内蔵パス一覧

| パス | 用途 | 利用できる条件 |
| --- | --- | --- |
| `/__select__` | サインイン済みユーザー向けのアプリ選択ページ | 常にゲートウェイで予約されます。セッションがなければサインインフローに進みます。カスタムサービススコープの認証情報では「内蔵選択ページ」も選択します。 |
| `/__wol__` | サインイン済みユーザー向けのデバイス起動ページ | WOL と `システム設定 → ゲートウェイ → ポータル → Wake-on-LAN ショートカットを表示` が有効な場合だけ使えます。カスタムスコープでは「内蔵 Wake-on-LAN ページ」も必要です。ショートカットを無効にすると、アップストリームへ渡らず Not Found になります。 |
| `/__auth__/login` | 同一オリジンのサインイン用フォールバック | 現在のサブドメインが認証 Host とルートドメイン Cookie を共有できないとき、保護されたサービス、選択ページ、WOL ページは現在のサブドメイン上のこのパスへ転送されます。 |
| `/__auth__/…` | 認証サービスの同一オリジンのページリソースと API | サインイン、サインアウト、コールバック、WOL ページのデータ取得に使用されます。独立したサービス入口ではありません。 |
| `/__assets__/…` | ゲートウェイのアイコンやツールバー用スクリプトなどの静的リソース | 内蔵ページとポータルが読み込みます。設定可能なページやファイルサービスではありません。 |

## アプリ選択ページ：`/__select__`

ゲートウェイに接続されている任意のサブドメインで `/__select__` を開くと、アプリ選択ページを表示できます。有効なセッションがなければ、認証後にこのページへ戻ります。サインイン後は、現在の認証情報から見えて利用可能な入口だけが表示されます。サブドメインルーティングでグループ表示を使う場合、同じグループと並び順が使われます。

![サインイン後のアプリ選択ページ。利用可能なサービス、Wake-on-LAN、サインアウトを表示](/images/gateway-built-in-pages/service-selection.webp)

カスタムサービススコープの TOTP またはユーザー名・パスワードのアカウントでは、`認証設定 → 権限` で「内蔵選択ページ」を選択してください。このページを開いても他サービスの権限は付与されず、各アプリを開くたびにログイン要件と認証情報のスコープが確認されます。

## デバイス起動ページ：`/__wol__`

`/__wol__` は、有効なデバイス名と簡易オンライン状態を表示して起動要求を送れる、簡易 Wake-on-LAN ページです。ポータルのショートカットから開くほか、`https://nas.example.com/__wol__` のように、ゲートウェイへ接続された任意のサブドメインで直接開けます。

![モバイルの Wake-on-LAN 内蔵ページ。デバイス状態と起動ボタンを表示](/images/gateway-built-in-pages/wake-on-lan-mobile.png)

`システム設定 → 機能 → Wake-on-LAN` で WOL を有効にし、`システム設定 → ゲートウェイ → ポータル` のショートカットを有効のままにします。全スコープの認証情報は直接利用できます。カスタムスコープでは内蔵 Wake-on-LAN ページも選択します。このページは MAC アドレス、IP アドレス、ブロードキャストアドレス、Relay、内部エラー詳細を公開しません。

## 同一オリジンのサインイン用フォールバック：`/__auth__/…`

`/__auth__/login` は、同じルートドメイン配下のサブドメインにおける標準のサインイン URL ではありません。ルートドメインが設定され、Cookie を共有できる場合、たとえば認証 Host が `auth.example.com`、アプリ Host が `nas.example.com` なら、保護されたサービスは共通の認証 Host へ転送され、作成されたセッションは互換性のある `*.example.com` Host で再利用できます。

現在のサブドメインが設定されたルートドメインの Cookie スコープ外である場合、またはドメイン設定のために認証 Host とログイン状態を共有できない場合に限り、ゲートウェイは現在のサブドメイン上の同一オリジン `/__auth__/…` を自動的に使います。たとえばルートドメインが `example.com` で、アクセス先が `nas.other-example.net` の場合、次の URL でサインインしてから元のサービスへ戻ります。

```text
https://nas.other-example.net/__auth__/login
```

このフォールバックは、そのサブドメイン自身の Cookie スコープでセッションを作成または利用します。認証 Host のルートドメイン配下にある共有セッションを取得することはできないため、互換性のない Host では個別のサインインが必要です。`/__auth__/api/auth/logout` などの API、OIDC コールバック、静的リソースも `/__auth__/…` に含まれます。これらはブラウザーセッション、リダイレクトパラメーター、または同一オリジン検証に依存するため、公開 API や通常のブックマークとして使わないでください。管理 API には [OpenAPI：管理 API の公開と AI Agent](/ja/guide/openapi) を使用します。

## 開けない場合

1. 管理入口 `7991` や内部認証ポート `7997` ではなく、ゲートウェイ入口を使っていることを確認します。
2. DNS、トンネル、手前のリバースプロキシがリクエストをゲートウェイへ送っており、HTTPS 証明書がそのサブドメインを含むことを確認します。
3. パスが正確か確認します。`/__select__/` と `/__wol__/` は内蔵ページのパスではありません。
4. 選択ページが繰り返しログインへ戻る場合は、セッション、認証 Host、ルートドメイン Cookie の範囲、手前のプロキシの `Host`、`X-Forwarded-Host`、`X-Forwarded-Proto` を確認します。ルートドメインをまたぐ Host では、自身の `/__auth__/…` と個別ログインが必要です。
5. WOL が Not Found になる、またはデバイスがない場合は、WOL 機能、ポータルショートカット、デバイスの有効状態、認証情報の内蔵 WOL ページ権限を順に確認します。
6. 外部ネットワークから拒否される場合は、ゲートウェイ可視性、WAF、ブロックリスト、スロットリング、リクエストログ内のクライアント IP を確認します。LAN からのアクセスは公開ネットワークの検証になりません。
