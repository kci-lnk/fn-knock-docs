# 閘道內建頁面

Go 閘道會先處理一組保留路徑，再決定是否將請求轉送給 Host 或路徑映射的上游服務。這些頁面不需要新增映射；只要某個子網域的請求實際到達閘道入口，就可以在該子網域後加上內建路徑存取。

例如，下列兩個位址由閘道本身回應，而不是由 `nas.example.com` 或 `auth.example.com` 對應的上游應用程式回應：

```text
https://nas.example.com/__select__
https://auth.example.com/__wol__
```

這裡的「任意子網域」是指 DNS、連接埠轉送或通道已將該子網域的 HTTP/HTTPS 請求送到 fn-knock 閘道；不要求該子網域另有一條子網域映射。憑證仍須涵蓋所用網域，前置 CDN、反向代理或通道也必須保留原始 `Host` 並將請求轉送到閘道入口。內建路徑只適用於 Web 閘道，不適用於管理入口、TCP/UDP 通訊協定映射或直連模式的原始連接埠。

路徑必須完全一致。`/__select__` 和 `/__wol__` 後方不要加入 `/`；可正常附加查詢參數。閘道可見性、WAF、全域封鎖清單與反向代理限流仍會在頁面回應前執行，因此也可能阻止請求。

## 內建路徑一覽

| 路徑 | 用途 | 何時可存取 |
| --- | --- | --- |
| `/__select__` | 已登入使用者的應用程式選擇頁 | 始終由閘道保留。未登入時會進入登入流程；自訂服務範圍的憑證還要勾選「內建選擇頁」。 |
| `/__wol__` | 已登入使用者的裝置喚醒頁 | 僅在 WOL 功能與 `系統設定 → 閘道 → 傳送門 → 顯示遠端喚醒快速入口` 已開啟時提供。未登入時會進入登入流程；自訂服務範圍還要勾選「內建遠端喚醒頁面」。關閉快速入口後會回傳找不到頁面，不會落到上游應用程式。 |
| `/__auth__/login` | 同源登入回退入口 | 當目前子網域無法與驗證 Host 共用根網域 Cookie 時，存取受保護服務、選擇頁或 WOL 頁面會自動跳轉到目前子網域的這個位址。排障時可直接開啟，但通常不必將它設為書籤。 |
| `/__auth__/…` | 驗證服務的同源頁面資源與 API | 用於登入、登出、回呼與 WOL 頁面的資料請求；由閘道轉交驗證服務，不是獨立業務服務入口。 |
| `/__assets__/…` | 閘道內建圖示、工具列指令碼等靜態資源 | 供內建頁面與傳送門載入；不是可設定的頁面或檔案服務。 |

## 應用程式選擇頁：`/__select__`

在瀏覽器開啟任一已接入閘道的子網域並加上 `/__select__`，即可進入應用程式選擇頁。沒有有效工作階段時，驗證完成後會回到該頁面；登入後頁面只會顯示目前憑證可見、且目前可用的入口。子網域映射使用群組檢視時，選擇頁會沿用相同的群組與排序。

![登入後的應用程式選擇頁，列出可存取服務並提供網路喚醒與登出入口](/images/gateway-built-in-pages/service-selection.webp)

自訂服務範圍的 TOTP 或帳號密碼帳號，需要在 `驗證設定 → 權限` 選擇「內建選擇頁」。僅開啟選擇頁不會授予其他服務權限；每次開啟應用程式時，閘道仍會依該服務的登入要求與憑證範圍驗證。

## 裝置喚醒頁：`/__wol__`

`/__wol__` 是精簡的 Wake-on-LAN 頁面，顯示已啟用裝置的名稱和簡化在線狀態，並可發起喚醒。它可由傳送門快速入口開啟，也可直接在任一已接入閘道的子網域存取，例如 `https://nas.example.com/__wol__`。

![行動裝置上的網路喚醒內建頁面，顯示裝置狀態和喚醒按鈕](/images/gateway-built-in-pages/wake-on-lan-mobile.png)

使用前需在 `系統設定 → 功能 → 遠端喚醒` 開啟 WOL，並在 `系統設定 → 閘道 → 傳送門` 保持「顯示遠端喚醒快速入口」開啟。全部範圍憑證可直接使用；自訂範圍憑證還必須選擇「內建遠端喚醒頁面」。頁面不會暴露裝置 MAC、IP、廣播位址、Relay 或內部錯誤細節。

## 同源登入回退與驗證路徑：`/__auth__/…`

`/__auth__/login` 並不是同根網域子網域的預設登入位址。已設定根網域且能共用 Cookie 時，例如驗證 Host 為 `auth.example.com`、業務 Host 為 `nas.example.com`，存取受保護服務會跳轉到統一的驗證 Host；登入後的工作階段可在相容的 `*.example.com` Host 之間重複使用。

只有當目前存取的子網域不在設定的根網域 Cookie 範圍內，或因網域設定無法與驗證 Host 共用登入狀態時，閘道才會自動使用目前子網域的同源 `/__auth__/…` 路徑。例如根網域為 `example.com`，但存取的是 `nas.other-example.net`，登入會在下列位址完成，再回到原始服務：

```text
https://nas.other-example.net/__auth__/login
```

這個回退流程會在該子網域自身的 Cookie 範圍內建立或使用工作階段，不能讓它取得驗證 Host 根網域下的共用登入狀態；因此不相容 Host 需要個別登入。`/__auth__/api/auth/logout` 等 API、OIDC 回呼與靜態資源同屬 `/__auth__/…`。這些位址依賴瀏覽器工作階段、跳轉參數或同源檢查，不應作為公開 API 或一般書籤。需要使用管理 API 時，請使用 [OpenAPI：開放管理 API 與 AI Agent](/zh-tw/guide/openapi)。

## 無法開啟時

1. 確認使用的是閘道入口，而非管理入口 `7991` 或內部驗證連接埠 `7997`。
2. 確認子網域的 DNS、通道或前置反向代理確實將請求送到閘道，且 HTTPS 憑證包含該子網域。
3. 檢查位址是否使用精確路徑；`/__select__/` 與 `/__wol__/` 不是內建頁面路徑。
4. 選擇頁反覆跳轉登入時，檢查工作階段、驗證 Host、根網域 Cookie 範圍，以及前置代理的 `Host`、`X-Forwarded-Host`、`X-Forwarded-Proto`；跨根網域 Host 應預期使用自身的 `/__auth__/…` 並個別登入。
5. WOL 回傳找不到頁面或沒有裝置時，依序檢查 WOL 功能、傳送門快速入口、裝置是否啟用與憑證的內建 WOL 頁面權限。
6. 從外網被拒絕時，檢查閘道可見性、WAF、封鎖清單、限流及請求記錄中的用戶端 IP；區域網路存取不能代替公網驗證。
