# 내비게이션 패널 동기화

`서브도메인 라우팅 → 내비게이션 패널로 동기화`는 활성화된 fn-knock 앱 항목을 Sun-Panel, OneNav 또는 Van-Nav에 단방향으로 게시합니다. 표시 제목, 공개 URL, 공개 아이콘, 선택적 그룹만 보내며 내부 Target, 인증 자격 증명, fn-knock 관리 권한은 내보내지 않습니다.

## 연결

1. 패널 유형과 전체 API URL을 입력합니다.
2. 필요한 계정이나 Token을 입력합니다. TLS 검증 무시는 신뢰 체인을 바로 고칠 수 없는 통제된 자체 서명 환경에서만 사용합니다.
3. fn-knock 그룹을 반영하거나 모든 앱을 한 카테고리에 배치합니다. 그룹 반영 모드는 네임스페이스를 지원하며 미분류 앱도 그곳에 배치합니다.
4. 초안을 저장하고 연결을 테스트합니다. 성공해야 미리보기와 동기화를 사용할 수 있습니다.

자격 증명은 암호화되어 현재 설치에 연결됩니다. `.knock` 백업을 복원하면 패널 자격 증명이 지워지고 연결이 미검증으로 바뀌며 자동 동기화도 꺼집니다.

## 미리보기와 적용

적용 전에는 항상 미리보기가 필요합니다. 생성, 갱신, 삭제, 변경 없음, 잔여 항목, 충돌을 표시하며 잠시 후 만료됩니다. 적용 시 원본 설정, 원격 상태, 계획 요약을 다시 확인하므로 변경이 있으면 새 미리보기가 필요합니다. 충돌이 있으면 적용하지 않습니다.

활성화된 일반 앱 Host만 포함하며 인증 서비스, 비활성 매핑, 내부 Target은 제외합니다. 공개 URL은 현재 도메인, 터널, 외부 포트 설정을 따릅니다. 패널에서 열어도 기존 인증, 가시성, WAF 정책이 계속 적용됩니다.

fn-knock는 이 연결이 등록한 원격 그룹과 링크만 변경하거나 삭제합니다. 이름이 같은 제3자 항목은 인수하지 않습니다. 등록된 항목을 패널에서 수동 변경하면 다음 동기화가 덮어쓸 수 있습니다.

## 자동 동기화와 공급자 차이

자동 동기화는 서브도메인 변경 시와 5~1440분 교정 주기로 실행됩니다. 실패와 복구는 이벤트 센터에 기록되며 실행 기록은 최대 20건, 30일 보관됩니다.

OneNav와 Van-Nav는 오래된 소유 항목을 정리할 수 있습니다. Sun-Panel은 안정적인 삭제 및 카테고리 이름 변경 API가 없어 잔여 항목을 수동 정리해야 할 수 있습니다. 연결 삭제는 기본적으로 원격 내용을 유지하며 선택적 정리도 해당 연결 소유 항목만 처리합니다. Sun-Panel은 연결 해제만 가능합니다.

## 보안과 문제 해결

- HTTPS와 최소 권한 계정을 사용하세요. TLS 검증 무시는 자격 증명 가로채기 위험을 높입니다.
- 테스트 후 미리보기가 실패하면 API 기본 경로, 권한, 동명 충돌을 확인하세요.
- 계획이 만료되면 이전 계획을 다시 보내지 말고 새로 미리보세요.
- 실행 기록과 이벤트에서 네트워크, 인증, 할당량, 잔여 항목 오류를 확인하세요.
- 연결 삭제 전에 원격 항목을 유지할지 결정하세요.
