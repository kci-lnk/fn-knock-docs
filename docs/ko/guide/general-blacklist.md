# 일반 차단 목록

일반 차단 목록은 명백하게 신뢰할 수 없는 공인 IP를 게이트웨이에서 거부합니다. 공격 출발지로 확인되었거나 비정상 동작이 계속되는 출발지를 처리할 때 적합합니다. 일시적인 서비스 오류, 프록시 주소 또는 불확실한 위치 정보만으로 차단 목록에 추가하면 안 됩니다.

정확한 IPv4 또는 IPv6 주소만 추가할 수 있고 CIDR은 지원하지 않습니다. 레코드는 자동으로 만료되지 않으므로 삭제할 때까지 계속 게이트웨이 판단에 사용됩니다.

## 추가 전에 출발지 확인

요청 로그, WAF 로그 또는 Host 활성 IP에서 실제 클라이언트 IP를 복사하는 것이 좋습니다. 다음 주소는 차단 목록에 추가하지 않습니다.

- `127.0.0.1`, 사설망, Docker 네트워크 대역 또는 리버스 프록시 노드 자체
- 공유 인터넷 출구, CDN 엣지 IP 또는 아직 확인하지 않은 VPN 출구
- 로그 문맥 없이 한 번만 나타난 출발지

업스트림 프록시를 잘못 차단하면 모든 사용자가 동시에 접속할 수 없게 됩니다.

## 레코드 추가

`세션 및 보안 → 일반 차단 목록`에서 ‘IP 추가’를 누릅니다.

1. 한 줄에 IP 하나를 입력합니다. 공백, 쉼표 또는 세미콜론으로 구분할 수도 있습니다.
2. 페이지에서 중복을 제거하고 제출할 IP 수를 표시합니다.
3. 필요하면 로그 시각, Host, Trace ID 또는 조치 사유를 메모에 기록합니다.
4. 차단 목록 추가를 확인합니다.

같은 IP가 이미 있으면 다시 추가할 때 기존 레코드가 업데이트됩니다. 성공 메시지에는 새로 추가된 수와 업데이트된 수가 각각 표시됩니다. 입력에 잘못된 주소가 하나라도 있으면 전체 제출이 실패하므로 모든 주소를 먼저 수정합니다.

출처 레이블은 추가한 화면에 따라 기록됩니다.

| 출처 | 생성 위치 |
| --- | --- |
| 수동 | `세션 및 보안 → 일반 차단 목록`의 추가 대화상자 |
| 요청 로그 | 요청 로그에서 IP 하나 또는 여러 개 차단 |
| 활성 IP | Host 활성 IP 목록 |
| WAF 로그 | WAF 로그에서 IP 하나 또는 여러 개 차단 |

출처와 메모는 감사 기록용이며 우선순위나 자동 차단 해제 조건을 뜻하지 않습니다.

## 확인 및 삭제

목록에는 IP, 위치, 출처, 메모, 생성 시각 및 업데이트 시각이 표시됩니다. IP, 출처 또는 메모 검색, 페이지 탐색, 개별 삭제 및 일괄 삭제도 지원합니다.

삭제하면 해당 IP는 게이트웨이의 일반 처리 절차로 돌아가지만 요청이 반드시 허용되는 것은 아닙니다. WAF, 스캐너 차단 목록, 게이트웨이 접근 범위, 인증 정책, SSH 방화벽 또는 업스트림 규칙에서 계속 거부할 수 있습니다.

요청 로그와 WAF 로그에서는 현재 IP가 일반 차단 목록에 있는지 확인하고 바로 차단하거나 차단을 해제할 수 있습니다. 조치 후 관련 로그 목록을 새로 고쳐 상태가 바뀌었는지 확인합니다.

## 다른 기능과의 관계

| 기능 | 더 적합한 상황 |
| --- | --- |
| 일반 차단 목록 | 확인된 공인 IP 하나를 즉시 거부해야 할 때 |
| 스캐너 차단 | 시스템이 비정상 경로 탐지에 따라 별도의 차단 목록을 자동 관리할 때 |
| WAF | HTTP 요청 내용 또는 규칙이 일치할 때 |
| 게이트웨이 접근 범위 | 허용할 지역 또는 CIDR을 미리 제한할 때 |
| IP 허용 목록 | 신뢰하는 고정 출발지를 명시적으로 허용할 때 |
| SSH 보안 | 호스트 SSH 포트의 출발지와 로그인 실패를 차단할 때 |

일반 차단 목록과 스캐너 차단 목록은 서로 독립된 레코드입니다. 일반 차단 목록에서 삭제해도 스캐너 차단은 해제되지 않으며 그 반대도 마찬가지입니다.

## 유지보수 권장 사항

- 추가할 때 ‘비정상’이라고만 쓰지 말고 증거와 사유를 남깁니다.
- 공유 인터넷 출구와 통신사 주소에는 재검토 날짜를 정하여 이후 사용자까지 장기간 잘못 차단하지 않도록 합니다.
- CDN 또는 리버스 프록시 트래픽을 처리하기 전에 ‘클라이언트 IP’와 ‘연결 출발지 IP’를 대조합니다.
- 업데이트 시각과 출처를 기준으로 오래된 레코드를 정기적으로 검토합니다.
- 프록시 노드를 잘못 차단했다면 신뢰할 수 있는 관리 엔드포인트에서 레코드를 삭제하고 실제 IP 전달 설정을 확인합니다.
