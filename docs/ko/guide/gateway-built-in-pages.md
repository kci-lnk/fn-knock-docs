# 게이트웨이 내장 페이지

Go 게이트웨이는 Host 또는 경로 매핑 업스트림으로 요청을 전달하기 전에 예약 경로 집합을 먼저 처리합니다. 이 페이지에는 별도 매핑이 필요하지 않습니다. 요청이 실제로 게이트웨이 입구에 도달하는 서브도메인이라면 그 뒤에 내장 경로를 붙여 열 수 있습니다.

예를 들어 다음 주소는 `nas.example.com` 또는 `auth.example.com`의 업스트림 애플리케이션이 아니라 게이트웨이 자체가 응답합니다.

```text
https://nas.example.com/__select__
https://auth.example.com/__wol__
```

여기서 “모든 서브도메인”은 DNS, 포트 포워딩 또는 터널을 통해 해당 HTTP/HTTPS 요청이 fn-knock 게이트웨이에 도달하는 서브도메인을 뜻합니다. 별도의 서브도메인 매핑은 필요하지 않습니다. 인증서는 사용하는 도메인을 포함해야 하며, 앞단 CDN·리버스 프록시·터널은 원래 `Host`를 보존하여 게이트웨이로 전달해야 합니다. 내장 경로는 Web 게이트웨이에만 적용되며 관리 입구, TCP/UDP 스트림 매핑, 직접 모드의 원래 포트에는 적용되지 않습니다.

경로는 정확히 일치해야 합니다. `/__select__`와 `/__wol__` 뒤에 `/`를 붙이지 마십시오. 쿼리 매개변수는 사용할 수 있습니다. 게이트웨이 가시성, WAF, 전역 차단 목록, 리버스 프록시 속도 제한은 페이지를 반환하기 전에도 실행되므로 요청을 차단할 수 있습니다.

## 내장 경로 목록

| 경로 | 용도 | 사용 조건 |
| --- | --- | --- |
| `/__select__` | 로그인한 사용자의 애플리케이션 선택 페이지 | 항상 게이트웨이에 예약됩니다. 세션이 없으면 로그인 흐름으로 이동합니다. 사용자 지정 서비스 범위 자격 증명에서는 내장 선택 페이지도 선택해야 합니다. |
| `/__wol__` | 로그인한 사용자의 장치 깨우기 페이지 | WOL과 `시스템 설정 → 게이트웨이 → 포털 → Wake-on-LAN 바로가기 표시`가 켜진 경우에만 사용할 수 있습니다. 사용자 지정 범위에서는 내장 Wake-on-LAN 페이지도 선택해야 합니다. 바로가기를 끄면 업스트림으로 전달되지 않고 Not Found가 반환됩니다. |
| `/__auth__/login` | 동일 출처 로그인 대체 입구 | 현재 서브도메인이 인증 Host와 루트 도메인 Cookie를 공유할 수 없을 때, 보호된 서비스·선택 페이지·WOL 페이지가 현재 서브도메인의 이 경로로 이동합니다. |
| `/__auth__/…` | 인증 서비스의 동일 출처 페이지 리소스 및 API | 로그인, 로그아웃, 콜백, WOL 페이지의 데이터 요청에 사용됩니다. 독립 서비스 입구가 아닙니다. |
| `/__assets__/…` | 게이트웨이 아이콘과 도구 모음 스크립트 등의 정적 리소스 | 내장 페이지와 포털에서 불러옵니다. 설정 가능한 페이지나 파일 서비스가 아닙니다. |

## 애플리케이션 선택 페이지: `/__select__`

게이트웨이에 연결된 임의의 서브도메인에서 `/__select__`를 열면 애플리케이션 선택 페이지를 표시할 수 있습니다. 유효한 세션이 없으면 인증 후 이 페이지로 돌아옵니다. 로그인 후에는 현재 자격 증명에서 볼 수 있고 현재 사용 가능한 입구만 표시됩니다. 서브도메인 라우팅이 그룹 보기를 사용하면 같은 그룹과 순서를 사용합니다.

![로그인 후 애플리케이션 선택 페이지. 접근 가능한 서비스, Wake-on-LAN, 로그아웃을 표시](/images/gateway-built-in-pages/service-selection.webp)

사용자 지정 서비스 범위의 TOTP 또는 사용자 이름·비밀번호 계정에서는 `인증 설정 → 권한`에서 내장 선택 페이지를 선택하십시오. 이 페이지를 연다고 다른 서비스 권한이 부여되지는 않으며, 각 애플리케이션을 열 때마다 로그인 요구 사항과 자격 증명 범위를 확인합니다.

## 장치 깨우기 페이지: `/__wol__`

`/__wol__`은 활성화된 장치의 이름과 간단한 온라인 상태를 보여 주고 깨우기 요청을 보낼 수 있는 간결한 Wake-on-LAN 페이지입니다. 포털 바로가기에서 열거나, `https://nas.example.com/__wol__`처럼 게이트웨이에 연결된 임의의 서브도메인에서 직접 열 수 있습니다.

![모바일 Wake-on-LAN 내장 페이지. 장치 상태와 깨우기 버튼을 표시](/images/gateway-built-in-pages/wake-on-lan-mobile.png)

`시스템 설정 → 기능 → Wake-on-LAN`에서 WOL을 켜고, `시스템 설정 → 게이트웨이 → 포털`의 Wake-on-LAN 바로가기를 켜 두십시오. 전체 범위 자격 증명은 바로 사용할 수 있으며, 사용자 지정 범위 자격 증명은 내장 Wake-on-LAN 페이지도 선택해야 합니다. 이 페이지는 장치 MAC 주소, IP 주소, 브로드캐스트 주소, Relay 또는 내부 오류 상세를 노출하지 않습니다.

## 동일 출처 로그인 대체 및 인증 경로: `/__auth__/…`

`/__auth__/login`은 같은 루트 도메인에 있는 서브도메인의 기본 로그인 주소가 아닙니다. 루트 도메인이 설정되어 Cookie를 공유할 수 있는 경우, 예를 들어 인증 Host가 `auth.example.com`이고 애플리케이션 Host가 `nas.example.com`이면 보호된 서비스는 공통 인증 Host로 이동합니다. 생성된 세션은 호환되는 `*.example.com` Host에서 재사용할 수 있습니다.

현재 서브도메인이 설정된 루트 도메인 Cookie 범위 밖에 있거나 도메인 구성 때문에 인증 Host와 로그인 상태를 공유할 수 없는 경우에만, 게이트웨이가 현재 서브도메인의 동일 출처 `/__auth__/…` 경로를 자동으로 사용합니다. 예를 들어 루트 도메인이 `example.com`인데 요청 Host가 `nas.other-example.net`이면, 다음 주소에서 로그인한 후 원래 서비스로 돌아갑니다.

```text
https://nas.other-example.net/__auth__/login
```

이 대체 흐름은 해당 서브도메인의 Cookie 범위에서 세션을 만들거나 사용합니다. 인증 Host의 루트 도메인 아래에서 공유하는 세션을 얻을 수 없으므로 호환되지 않는 Host는 별도 로그인이 필요합니다. `/__auth__/api/auth/logout` 같은 API, OIDC 콜백, 정적 리소스도 `/__auth__/…`에 속합니다. 이 주소는 브라우저 세션, 리디렉션 매개변수 또는 동일 출처 검사에 의존하므로 공개 API나 일반 북마크로 사용하면 안 됩니다. 관리 API는 [OpenAPI: 관리 API 공개와 AI Agent](/ko/guide/openapi)를 사용하십시오.

## 페이지가 열리지 않을 때

1. 관리 입구 `7991`이나 내부 인증 포트 `7997`이 아니라 게이트웨이 입구를 사용했는지 확인합니다.
2. 서브도메인의 DNS, 터널, 앞단 리버스 프록시가 요청을 실제로 게이트웨이로 보내며 HTTPS 인증서가 해당 서브도메인을 포함하는지 확인합니다.
3. 경로가 정확한지 확인합니다. `/__select__/`와 `/__wol__/`은 내장 페이지 경로가 아닙니다.
4. 선택 페이지가 계속 로그인으로 돌아가면 세션, 인증 Host, 루트 도메인 Cookie 범위, 앞단 프록시의 `Host`, `X-Forwarded-Host`, `X-Forwarded-Proto`를 확인합니다. 루트 도메인이 다른 Host에서는 자체 `/__auth__/…`와 별도 로그인이 필요합니다.
5. WOL이 Not Found를 반환하거나 장치가 없으면 WOL 기능, 포털 바로가기, 장치 활성 상태, 자격 증명의 내장 WOL 페이지 권한을 순서대로 확인합니다.
6. 외부 네트워크에서 거부되면 게이트웨이 가시성, WAF, 차단 목록, 속도 제한, 요청 로그의 클라이언트 IP를 확인합니다. LAN 접속은 공용 네트워크 검증을 대신할 수 없습니다.
