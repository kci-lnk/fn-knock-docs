# 网关内置页面

Go 网关会优先处理一组保留路径，再决定是否把请求转发给 Host 或路径映射的上游服务。这些页面不需要新建映射；只要某个子域的请求实际到达网关入口，就可以在该子域后附加内置路径访问。

例如，以下两个地址会由网关本身响应，而不是由 `nas.example.com` 或 `auth.example.com` 对应的上游应用响应：

```text
https://nas.example.com/__select__
https://auth.example.com/__wol__
```

这里的“任意子域”是指 DNS、端口转发或隧道已经把该子域的 HTTP/HTTPS 请求送到 fn-knock 网关的子域；它不要求该子域另有一条子域映射。证书仍需覆盖所用域名，前置 CDN、反向代理或隧道也必须保留原始 `Host` 并把请求转发到网关入口。内置路径仅适用于 Web 网关，不适用于管理入口、TCP/UDP 协议映射或直连模式的原始端口。

路径必须完全一致。`/__select__` 和 `/__wol__` 后面不要增加 `/`；可以正常附加查询参数。网关可见性、WAF、通用黑名单和反代限流仍会在页面返回前执行，因此它们也可能阻止请求。

## 内置路径一览

| 路径 | 用途 | 何时可访问 |
| --- | --- | --- |
| `/__select__` | 已登录用户的应用选择页 | 始终由网关保留。未登录时会进入登录流程；自定义服务范围的凭据还要勾选“内置选择页”。 |
| `/__wol__` | 已登录用户的设备唤醒页 | 仅在 WOL 功能和 `系统设置 → 网关 → 传送门 → 显示远程唤醒快捷入口` 已开启时提供。未登录时会进入登录流程；自定义服务范围还要勾选“内置远程唤醒页面”。关闭快捷入口后返回未找到页面，不会落到上游应用。 |
| `/__auth__/login` | 同源登录回退入口 | 当当前子域无法与认证 Host 共享根域 Cookie 时，访问受保护服务、选择页或 WOL 页面会自动跳转到当前子域的这个地址。需要排障时可以直接打开，但一般不必把它作为书签。 |
| `/__auth__/…` | 认证服务的同源页面资源与接口 | 用于登录、退出、回调和 WOL 页面的数据请求；由网关转交认证服务，不是独立业务服务入口。 |
| `/__assets__/…` | 网关内置图标和工具栏脚本等静态资源 | 供内置页面和传送门加载；它不是可配置的页面或文件服务。 |

## 应用选择页：`/__select__`

在浏览器打开任一已接入网关的子域并加上 `/__select__`，即可进入应用选择页。没有有效会话时，认证完成后会回到该页面；登录后页面只显示当前凭据可见、且当前可用的入口。子域映射使用分组视图时，选择页会沿用相同的分组和排序。

![已登录后的应用选择页，列出可访问服务并提供网络唤醒和退出登录入口](/images/gateway-built-in-pages/service-selection.webp)

自定义服务范围的 TOTP 或账号密码账号需要在 `认证配置 → 权限` 中选择“内置选择页”。仅打开选择页不会授予其他服务权限；每次打开应用时，网关仍按该服务的登录要求和凭据范围验证。

## 设备唤醒页：`/__wol__`

`/__wol__` 是精简的 Wake-on-LAN 页面，显示已启用设备的名称和简化在线状态，并可发起唤醒。它既可由传送门快捷入口打开，也可直接使用任一已接入网关的子域访问，例如 `https://nas.example.com/__wol__`。

![移动端的网络唤醒内置页面，显示设备状态和唤醒按钮](/images/gateway-built-in-pages/wake-on-lan-mobile.png)

使用前需要在 `系统设置 → 功能 → 远程唤醒` 开启 WOL，并在 `系统设置 → 网关 → 传送门` 保持“显示远程唤醒快捷入口”开启。全部范围凭据可直接使用；自定义范围凭据还必须选择“内置远程唤醒页面”。页面不会暴露设备 MAC、IP、广播地址、Relay 或内部错误详情。

## 同源登录回退与认证路径：`/__auth__/…`

`/__auth__/login` 不是同根域子域的默认登录地址。已配置根域且能够共享 Cookie 时，例如认证 Host 为 `auth.example.com`、业务 Host 为 `nas.example.com`，访问受保护服务会跳转到统一的认证 Host；登录后的会话可在兼容的 `*.example.com` Host 之间复用。

当当前访问的子域不在设置的根域 Cookie 范围内，或因域名配置无法与认证 Host 共享登录态时，网关才会自动使用当前子域的同源 `/__auth__/…` 路径。例如根域为 `example.com`，但访问的是 `nas.other-example.net`，登录会在以下地址完成，再回到原始服务：

```text
https://nas.other-example.net/__auth__/login
```

这个回退流程会在该子域自己的 Cookie 范围内创建或使用会话，不能让它获得认证 Host 根域下的共享登录态；因此不兼容 Host 需要单独登录。`/__auth__/api/auth/logout` 等 API、OIDC 回调和静态资源同属 `/__auth__/…`。这些地址依赖浏览器会话、回跳参数或同源校验，不应被当作公开 API 或常规书签。需要使用管理 API 时，应使用 [OpenAPI：开放管理 API 与 AI Agent](/guide/openapi)。

## 无法打开时

1. 确认使用的是网关入口，而不是管理入口 `7991` 或内部认证端口 `7997`。
2. 确认子域的 DNS、隧道或前置反向代理确实把请求送到网关，并且 HTTPS 证书包含该子域。
3. 检查地址是否使用精确路径；`/__select__/` 与 `/__wol__/` 不是内置页面路径。
4. 选择页反复跳转登录时，检查会话、认证 Host、根域 Cookie 范围和前置代理的 `Host`、`X-Forwarded-Host`、`X-Forwarded-Proto`；跨根域 Host 应预期使用自身的 `/__auth__/…` 并单独登录。
5. WOL 返回未找到或没有设备时，依次检查 WOL 功能、传送门快捷入口、设备是否启用和凭据的内置 WOL 页面权限。
6. 从外网被拒绝时，检查网关可见性、WAF、黑名单、限流以及请求日志中的客户端 IP；局域网访问不能代替公网验证。
